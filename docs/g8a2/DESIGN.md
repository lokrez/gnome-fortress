# Endless Chronicle design

Preserve the existing G5 reader/writer/checksums/transactions and all session/writer locks. Optimize only disposable IPC preparation. Before measurements and baseline fixtures are in evidence/before.json; fixture paths refer to newly generated temporary IPC blobs, never the owner world.

Prepare fixed-size event segments and individual terminal-agent records incrementally on the gameplay thread. Cached values are immutable pickle bytes. Attribute/container mutation instrumentation invalidates prepared records; mutable living agents, cells, intervention ledgers, RNG and scheduler are copied at the actual snapshot boundary. An outer detached payload carries prepared bytes plus unprepared current records. The spawned worker assembles the exact full World, then invokes the unchanged strict save callback. The checkpoint remains fully self-contained and readable by the accepted reader.

A small per-frame `prepare` hook belongs to the worker, not simulation ticks or rendering. The default/legacy worker has no hook. Preparation is budgeted and disposable. First manual/cold saves may use a safe full tail and remain slower; ordinary warm captures must not traverse old event contents. Cache invalidation, retries and worker crashes cannot publish partial history. No fork, thread reading of live data, persistent cache, delta checkpoint or new file format.

Verification gates: focused invalidation/detachment tests; existing Saveguard subprocess failures; matched no-save/reference/optimized runs and accepted-reader compatibility; generated mature-world benchmarks and actual Pygame frame traces; full fast suite and protected-source audit. Extend beyond 26k only after estimating measured costs. Do not optimize the strict persistence writer unless profiling proves it blocks the owner thread.

## Implemented boundary

`Chronicle` prepares 128-event blocks and individual terminal-agent blocks. It uses weak mutation callbacks, avoiding record/cache ownership cycles. A cold scan discovers terminal agents once; later births use `next_id`, and deaths use the living-set difference. Replaced dead references are copied immediately and queued for re-preparation. Event journal identity/revision and tick rewinds invalidate the relevant cache. Normal model fields remain unchanged; `asdict`, JSON and dataclass value equality remain compatible.

The owner-thread capture pickles only the mutable hot graph (about 0.84 MiB at 26k), then makes immutable tuples of prepared byte references and ID ordering. A frozen `PreparedPayload` contains no live references. The pool feeder copies historical bytes asynchronously; the spawned worker checks the writer gate and owner PID before assembling the World. Strict storage then validates and writes a complete ordinary G5 checkpoint. Standalone `Chronicle.capture` is a bytes convenience API; its full envelope encode time is NOT the production main-thread capture time.

Incomplete preparation includes the uncached current tail; zero prepared history uses the accepted full-copy fallback. A first immediate manual save can therefore retain the old cold hitch. The 4 ms preparation budget is soft: one block, allocation/GC or OS scheduling can exceed it. No GC disabling, unsafe fork or unchecked cross-thread objects were introduced. Ordinary completed preparation only handles new history.

Cache lifetime is one live World, not one generation per save. Old byte versions survive only while one in-flight immutable payload still needs them. Source records keep weak notification links; replacing/resetting caches does not keep old worlds alive through callbacks. Corrupt payloads fail in the worker; non-storage errors invalidate preparation before explicit retry. Storage errors keep valid prepared history, preventing an unnecessary cold retry. Worker crashes recreate the pool as before. There is still only one active save plus the original bounded Boolean request flag.

Preparation changes concrete historical Python objects into instrumented dataclass subtypes and wraps their owned nested containers. The simulation never branches on those concrete types. Normal attribute/list/dict edits and value equality are preserved; exact `type(x) is Event` introspection and retained aliases to replaced internal dictionaries are not a supported extension API. Direct low-level mutation bypasses require `chronicle.invalidate()`. Research worlds and public save data never contain these instrumentation classes. The cache is not a tamper-resistant archive; persistent checksums/validation remain authoritative.

Multiple preparers on the same live World use a weak journal ownership lease. Taking over invalidates the previous cache, preventing competing mutation callbacks from leaving another controller's bytes stale. This is separate from, and does not replace, the unchanged process/file ownership locks.
